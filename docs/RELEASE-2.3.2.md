# v2.3.2：模型设置、联网诊断与选题稳定性

## 设置与能力测试

- 合并重复接口控件，统一为“文本与工具接口”；协议名称说明请求格式，不代表模型品牌。模型原生联网接口独立配置，测试不改变创作分工。
- 保留已有 Token 数值，将字段改为“单次回复上限（Token）”，解释与文章字数、上下文容量的区别，以及过低截断、过高被拒绝的可能性。
- 未配置原生搜索时明确“尚未发送搜索请求”，不推断模型不支持联网；说明 DeepSeek 的兼容 Messages 搜索取决于当前服务商是否开放。
- 文本测试标明 256 Token 小样本；工具测试使用实际输出上限与温度。第一轮要求调用工具，第二轮允许返回工具结果；基础测试不代表完整选题成功。
- 测试记录包含实际参数和测试版本。相关设置或测试实现改变后需要重新验证，旧测试不冒充当前配置结论。
- 保存及测试过程中锁定设置控件，避免返回的旧配置覆盖刚刚修改的联网接口。

## 执行与错误诊断

- 原生创作明确要求工具调用：Chat／Responses 为 required，Messages 为 any；实际产物仍须通过 Finish 校验。
- 完整响应缺少工具调用时，每个任务最多一次保留上下文的纠正，计入原请求上限。第二次缺失停止并保留文件；明确拒答、截断、格式错误、网络及 HTTP 错误不纠正。
- 区分空结果、缺少工具、截断、拒答、格式异常、缺少搜索证据与服务错误；收到 HTTP 200 的空结果不会显示成“未收到响应”。
- 验证响应前保存安全的结束原因、数量、参数和用量。已知用量保留，未知费用不当作零；诊断不保存凭证或请求头。
- 原生搜索和工具执行不吞掉取消、预算耗尽及明确服务错误；只有可恢复的接入／证据缺口可使用已允许的后备渠道。
- 接口只增加可选诊断字段，兼容历史任务；模型路由、文章内容、默认超时与请求限额保持原设置。
