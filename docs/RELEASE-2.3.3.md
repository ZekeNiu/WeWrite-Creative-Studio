# v2.3.3：DeepSeek 官方联网与模型列表

## 原因与修复

原程序共用一个基础地址读取模型和发送消息，导致 DeepSeek 官方的 `/anthropic` 入口被拼接为不存在的 `/anthropic/v1/models`。本版仅对官方域名识别其已知入口，模型目录使用 `/v1/models`，Messages 使用 `/anthropic/v1/messages`；中转服务地址及凭证所在域名保持原配置。

原搜索实现把结果块数量当作工具调用次数，且统一要求一次请求内只搜索一次。即使接口返回真实来源，也会因此把整个联网测试判为失败，并错误显示“中转站未遵守上限”。本版按工具调用编号去重，分别记录外部请求、内部调用、结果块和来源数量。

按用户确认的边界，DeepSeek 官方内部多次搜索可返回有效来源，界面同时提示内部次数与费用可能无法提前严格限制；工作台实际发出的请求继续受原总预算约束。其他 Messages／Responses 服务保留原次数限制，Gemini 保留已有内部查询统计。仅文字声称联网、无工具记录、无有效来源均不能通过。

能力测试及任务新增可选 `search_diagnostic`，在结果校验前记录安全的数量、HTTP 状态、服务身份、用量、限制情况和提示。调用编号仅保存不可逆摘要，不记录凭证、请求头或原始正文。失败时保留已知用量，未知费用不算零。HTTP 错误、取消与预算耗尽不重试、不被后备搜索吞掉。

联网测试版本更新为 2.3.3；文本、普通工具、图片测试仍使用既有测试版本，避免无关测试结果失效。

## 实际验证

- 首组定向检查 51 项通过；补充搜索相关检查 31 项通过（两组有重复用例），覆盖官方地址、非官方域名隔离、JSON／流式结果去重、多次内部搜索、来源证据、已知用量、HTTP 错误、取消、预算以及能力缓存。
- 前端类型检查与生产构建通过。本版按用户要求未运行全量后端测试及整套浏览器验收，提交使用 `[skip ci]` 跳过本次自动全量流程，后续工作流配置保持不变。
- 真实验证只进行一次模型目录查询和一次付费搜索请求：目录正常返回模型；搜索返回 HTTP 200、两个不同工具调用、两个结果块、10 个去重来源，通过联网测试。返回输入 11,315 Token、输出 1,093 Token；费用估算因价格信息不完整保持未知。
- 本次真实响应中两个调用编号不同，说明确实包含多次内部搜索，而非重复结果块；旧版的一次内部搜索限制会拒绝这类有效结果。重复结果块计数问题另由模拟用例覆盖。
- 来源中包括可打开的 [WHO 身体活动官方页面](https://www.who.int/zh/news-room/fact-sheets/detail/physical-activity)。联网通过已写入实际工作区的能力卡片，原有文本与工具测试通过记录仍有效。
- 本轮未运行完整选题，不将搜索验证替代完整创作验收。未追加其他厂商或重试调用。
