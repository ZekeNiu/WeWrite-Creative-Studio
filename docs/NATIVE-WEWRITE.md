# 工作台如何执行 WeWrite

原生化分三批交付。2.0 恢复创作核心；2.1 接入账号学习和原生粘贴排版；2.2 补齐独立扩展动作。上游不是单一写作 API，而是技能、执行环境和确定性命令的组合。保持这些条件一致不意味着逐字输出一致。

## 固定上游与真实执行

固定 `4.2.1 / e8df474ea8d9fd1b06b474115cee568dc46c9ab2`。`vendor/wewrite/UPSTREAM_MANIFEST.json` 对原始文件保存 SHA-256（统一 CRLF/LF）；每次执行校验。工作台直接导入所附源码；命令在独立子进程中执行同一份源码，不依赖机器上碰巧安装的其他版本。

每次执行有独立 `data/native/<execution_id>`、`WEWRITE_HOME` 和上游 run_id。加载完整主技能、当前模块、必读参考和所选人格，记录文件哈希；模型可以使用 Read、Find、List 补读其他参考及完整材料，通过 Write、Edit、受控 WeWrite 命令保存实际产物。WebFetch 复用现有原文读取器，不将搜索摘要当全文。

三种现有文本协议均支持多轮工具对话。Responses 保留全部返回项目及推理内容；Messages 保留工具及签名块，Chat 保留 tool_calls 和对应结果。连接测试分别检验文本与两轮工具往返，不将文本成功当成 Agent 成功。协议实现参考 [OpenAI 的推理与工具上下文说明](https://developers.openai.com/api/docs/guides/reasoning)。创作请求明确要求调用工具。完整响应缺少工具调用时，每个任务最多一次保留上下文的纠正，计入实际用量记录；再次缺失则分类失败并保留产物。拒答、截断、格式异常和网络／HTTP 错误不纠正，不退回旧写作提示。工具探测第一轮要求调用，第二轮允许返回实际工具结果，使用配置中的输出上限和温度。

## 界面与上游的关系

| 界面动作 | 上游过程 | 交接产物 |
|---|---|---|
| 选题 | wewrite-topic | topics.yaml |
| 资料整理 | wewrite-write 任务书、主张与内容增强准备 | brief.yaml / claims.yaml / sources.yaml |
| 大纲 | wewrite-write 框架与章节推进 | brief.yaml.sections |
| 写作、选段修改 | wewrite-write | draft.md / replacement.md |
| 审核、整体编辑 | wewrite-review，最多两轮 | assessment.yaml / review-report.json / article.md |
| 配图方案 | wewrite-visual 提示词模式 | images.json |

七阶段界面是暂停与人工操作的边界，不另立写作标准。自动继续沿用每篇设置；选题候选、人工决定、资料使用要求和完整原文可被模型读取。默认不调用原先的强化研究、论证综合、逐段事实检查或额外编辑循环。素材页仍可单独启动强化研究，结果保留在同一文章和来源集合中。

原生主张不会再因缺少本地强化研究的额外评判字段而被自动降级。旧记录及其问题处理仍可查看；人工决定、来源存在性、引用、有效文件、权限和版本冲突继续由代码检查。

从 2.4 起，素材页主按钮明确执行原生 `sources`，补充检索要求传入同一任务；`research` 由“深入核实”及具体问题的核实动作启动。详细研究记录保留在文章与历史任务中，原生准备只接收精简的 `research-evidence.yaml` 作为核实线索，再生成稿件使用的 `claims.yaml`。已确认的原生主张可直接复用。选题的暂定 takeaway 不再直接填入任务书的已知结论，未选候选与旧批次不进入后续研究或写作。

内部条件检查继续核对事实和适用范围，写作适配层负责区分哪些信息会影响读者理解或行动。重新整理后，旧深入核实记录折叠为历史，人工决定保留；核心立意仍缺依据时暂停自动继续。已有全文的 WebFetch 返回本地原文路径，明确要求更新时使用 refresh；被排除资料及其已知身份别名优先阻止读取，也不作为搜索片段提供给模型。

审稿输入是当前稿、简明待处理事项与原文路径，详细旧报告不反复回灌。编辑报告必须实际由上游 content-eval 产生，并与稿件内容绑定；后改稿件会使报告失效。通过门槛直接采用上游计算，轻微建议不触发额外改写。通过后执行上游封存；未通过保留待处理状态。

## 数据与费用

SQLite 是人工状态的权威来源，上游文件是该次任务的输入副本与产物。只有文章和账号版本仍匹配时才事务回写；修改候选单独保存，采用时再次检查。取消、中断或冲突均保留本次文件，可在“上游执行记录”查看。旧文章继续创作时才建立副本，不迁移另一部署，也不自动付费重读历史。

上游按网址和主张建立账本，适配层将同一资料的多条主张归回工作台稳定来源编号，保留主张记录。被用户排除的资料不能通过网页读取悄悄重新采用。技能、原文和任务状态文件受路径与写入权限保护；模型不能运行任意 shell、读其他任务或改写凭证。

文本、工具内付费搜索、图片、连接测试和失败请求均留用量记录，未知费用不记为零。工作台不再设置总请求、金额、搜索或读取上限；保留证据充分、无有效新线索等正常收尾条件及人工停止。独立诊断设置的用量范围不改变产品执行参数。

## 验收边界

离线模型返回是合成数据；真正运行工具循环、文件操作、上游命令、版本保护和界面。这证明软件交接与恢复行为，不证明真实模型会遵守所有技能、也不证明文笔优于旧版。真实质量对照需要相同模型、参数、人格、任务、材料及执行条件，并单独报告结果。未知中转价格不能用其他供应商官网价格代替。

## 账号和排版（2.1）

账号设置映射为上游 style.yaml，历史写入 history.yaml，已启用偏好按明确改稿对投影为 lessons，再调用上游 learn-edits --summarize。置信度、重复提升和衰减直接使用上游算法，不再使用自定义90天半衰期。栏目范围先筛选，上游人格／框架等范围继续生效；停用与撤销记录不重新启用。人工编辑规则会重置学习次数，来源记录仍保留。

人工改稿学习执行完整 wewrite-learn，通过真实 diff、文件读写和类型化模式，保留原稿／人工稿对，用户确认仍由界面完成。导入范文用上游本地提取，不调用模型；按栏目和类型选择最多两份，提供真实表达片段及所有权标记，不允许复用私人经历。旧范文无需付费重处理。

排版复用 make_paste_safe 和 validate_html，清洗保留 leaf；界面显示兼容性结果。封面独立保留在分享包和图片栏，不默认加入正文。配图数量为上限，原下拉框、颜色圆点、参数和手机预览不变。搜索和原文读取的实际用量跨原生阶段记录。

## 扩展动作（2.2）

v2.3.8 将这些动作分配到写作设置、排版导出及账号弹窗的对应位置，执行仍复用以下上游能力。旧执行接口保留；新增只读 `/api/extensions/jobs` 支持重复的 `action` 参数、可选 `article_id` 与分页，返回 `items`、`active`、`total`、`page`、`page_size`。动作与文章先筛选再分页；省略文章时可读取跨文章的排版学习历史，兼容旧记录，无数据库迁移。账号流程的检查与暂缓事项见 [说明](ACCOUNT-WORKFLOW-REVIEW.md)。

- 自定义人格以完整上游人格为基础保存，进入原人格选项；每次执行复制选定版本、加载全文并记录哈希，账号变更仍受版本保护。
- 主题学习读取公开公众号原始 HTML，使用上游 extract_styles / analyze_styles / generate_theme_yaml，加入原排版下拉。无原始样式时明确失败，不让模型猜一个主题。
- 多平台改写加载完整 wewrite-rewrite、必读资料及所选平台文件，源稿只读；真实调用 score / similarity，最多初稿加两次重试。小红书与抖音独立保存，数值或字数仍有问题时保留待处理，不为全绿反复重写。
- 公众号文章和图片帖必须单独启动并绑定当前预览、文章版本、账号版本和凭证标识。草稿箱复用上游 get_access_token / upload_image / upload_thumb / create_draft / create_image_post；发布使用当前预览 HTML，避免丢失工作台既有主题和字号。摘要未填写时采用上游转换器生成结果。不会调用正式发表接口。
- 读取远端草稿保存为独立副本，不自动覆盖原稿或把它推定为人工定稿；可以查看和下载后明确编辑。
- 在线效果复用上游 fetch_article_total；保留实际返回记录，按明确 msgid 关联，不用标题兜底，不将缺失补零。草稿 media_id 与统计 msgid 分开。已回填和手动效果进入原生 history.yaml，可独立执行 wewrite-stats 复盘。
- 阅读与结构建议也走原生执行层；默认调度中删除旧创作与额外审核循环的不可达分支。兼容旧记录及可选强化研究所需的函数仍保留，不作为失败后的自动退路。

微信凭证由 Windows 加密，仅通过子进程标准输入提供；不进入模型上下文、命令行、日志或分享包。微信请求逐项留回执，不自动重试。取消等待已发出请求返回，再停止后续动作；后台重启阻止子进程继续请求，并恢复迟到回执。网络断连时远端可能已成功，界面明确结果未知。无凭证或接口权限时保留所有本地成果。

这层适配保留了必要的确定性保护：公开网址与路径限制、明确的微信文章身份、版本冲突、幂等动作编号和凭证隔离。它们不另立写作规则。微信真实权限、真实编辑器粘贴和模型实际创作品质须与离线软件验收分开看待。
