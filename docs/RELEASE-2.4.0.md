# v2.4.0：围绕读者问题整理素材与写作

此前素材主入口会进入扩展研究流程，选题中的部分核心线索又会被过严的绑定规则丢弃，导致工作集中在旁支条件。详细核查记录与暂定结论还会进入稿件准备输入，使文章容易沿着核查过程展开。

本版将默认素材整理接回固定版本的 WeWrite 流程，深入核实作为独立动作保留。任务的读者问题、待核实线索、内部证据和稿件主张分开传递；原生素材完成后记录其依赖，后续阶段可识别未变的已完成工作。没有修改 vendor 中的上游功能、技能或提示词。

- 已采用的选题线索可绑定既有问题，不再因措辞差异被静默丢弃；模型扩展问题不自动成为用户要求。
- 摘录优先匹配当前问题，保留精确位置及按需回读。已有全文可以复用，明确检查网页更新时仍会重新读取。
- 独立核查一次返回事实支持与条件判断，程序分别验证；缺项才补查，不将省略核查等同于通过。覆盖判断按问题及证据依赖复用，新的相关反证仍触发核查。
- 不同渠道只重复返回已检查线索且无进展时暂停该路径，继续其他问题。没有新增产品时长、调用、金额或 Token 上限。
- 素材行显示已有记录能支持的用途、选题关联或简短摘要。未采用仍表示完全排除；已知身份别名及搜索片段也会检查。历史核实记录与当前整理结果分开，人工决定保留。
- 保持原界面风格、筛选分页、素材采用逻辑及排版导出控件。旧文章需主动重新整理或生成大纲，已有稿件不会被自动改写。

本地定向后端回归、前端构建、素材默认入口与深入核实入口、桌面/手机布局，以及完整创作和关键界面回归已通过。CI 增加素材交互检查，并将验收窗口从 20 分钟调整为 30 分钟，使后端与浏览器检查能够完整结束。

一次隔离副本实测完成了素材整理：15 次计量请求、约 266.5 秒、8 条主张、无待人工处理的核心缺口。此样本使用已有资料，不是从零检索对照；后续大纲在该次诊断总计 40 次请求处停止。由此发现的重复下载及阶段交接问题已补充修正并做离线回归。此次没有完成完整正文质量对照，不据此宣称所有选题的速度或文笔均已验证。真实文章、来源选择、账号配置及凭证没有随测试改写。
