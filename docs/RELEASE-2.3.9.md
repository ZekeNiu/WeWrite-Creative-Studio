# v2.3.9 修复换一批选题后没有新候选

选题文件包含未正确转义的引号时，YAML 解析异常原先会直接终止任务，没有进入已有的工具纠错流程。新候选因此无法保存到选题列表，任务只显示通用失败提示。

本版将文件格式错误转为可修正的校验结果，提供文件名、行、列和修正说明，由当前任务继续修正产物。只有格式和选题内容均通过既有校验后，才替换可见候选；修正过程中及服务失败时保留上一批。选题输出说明补充转义要求，并允许写入等价 JSON 对象，避免正文中的引号、冒号和换行破坏文件格式。

沿用固定的上游 WeWrite 4.2.1、任务接口、候选历史和人工采用方式，不调整模型服务参数，不修改上游技能，不迁移或重写个人文章。

验证全部使用临时模拟数据和模拟模型：

- 先复现原故障，再通过 8 项新增回归：三类 YAML 格式错误、特殊标点与换行保留、Chat／Responses／Anthropic 三种接口的同任务修正与连续换批、服务失败后保留旧候选。
- 相关原生执行、创作状态、工作流修复及工作台回归 74 项通过。
- 前端类型检查和生产构建通过；桌面与手机浏览器完成连续三批选题、反馈保存、刷新恢复和采用主题，并通过现有完整创作、账号、功能入口和保存恢复交互检查。

应用版本、锁文件、后端读取版本及预构建 `dist` 已同步。实际工作区无活动任务时安全切换到 v2.3.9，五个实际提供的界面文件与构建产物逐字节一致，再次打开启动器复用同一后台。文章、历史版本、设置、凭证和账号记录切换前后校验一致。已打开的页面需刷新。

本次没有调用真实付费模型。个人文章、凭证、数据及本地诊断记录不进入仓库。
