# 内容质量实现复核与最终边界

四批软件功能已完成发布，交付、验证、实际服务与私有记录保护见[v1.9.0及四批归档](RELEASE-1.9.0.md)。历史真实失败仍是失败；软件发布不等于模型在所有语义题或真实文章中均成功。

## 公众号表达与职责

这是公众号工作台。事实边界自然融入句意，本篇明确要求优先，不能因此改成科研报告或核查报告，不能改变用户语气、体裁或论证主线。核查过程、内部字段和资料缺口通常留在工作台；机制、反方、局限按文章需要安排，不强制各占一节。

上游WeWrite固定4.2.1（e8df474ea8d9fd1b06b474115cee568dc46c9ab2），其编辑原则基本合理。[主技能](../vendor/wewrite/skills/wewrite/SKILL.md)、[写作技能](../vendor/wewrite/skills/wewrite-write/SKILL.md)和[编辑技能](../vendor/wewrite/skills/wewrite-review/SKILL.md)是参考。应用的prompts.py只加载部分编辑、结构与人格材料，没有运行上游整套命令程序。研究调度由research.py另行实现，不能把应用的成本或判断问题都归因于上游。

第三批删去上游命令行文件创建与重复自动交付要求，保留编辑原则、人格、结构及来源保护；写作系统提示由7465减到5173字符。研究按一轮问题／每两条延期来源集中评估；正文审核直接复用独立事实核查，不先重跑完整研究。事实核查不接收旧AI自评或第四批软参考。研究来源政策37、编辑版本2保持。

## 代码与模型的边界

| 事项 | 实现责任 |
|---|---|
| 实际来源读取、身份与引用绑定 | 保存原文范围、出处与稳定编号，不能用元数据或下载成功替代真正提供给核查的原文 |
| 唯一完整结构、缓存、并发、取消、预算 | 由代码校验，未知判断不算支持，人工修改和撤销不能被后台覆盖 |
| 语义、否定、因果、原意和外推 | 先检查实际提示、上下文与任务拆分，复用已有独立核查和最多两轮整体编辑 |
| 账号与长期参考 | 单账号、默认栏目隔离，明确人工改稿对软学习；固定和扩大需作者确认，范文仅学表达 |
| 效果反馈 | 同窗口、独立文章、每指标至少五篇；未知不记零，只描述样本，不推因果 |

不靠题目／域名白名单、无限词表、更多模型审查层或反复换题补齐模型能力。已有一次材料修正、两轮整体编辑、人工采用／拒绝、定稿和历史恢复保留。第四批新增SQLite记录与每次调用的参考快照；运行中账号变更时旧结果仅保留候选，保存事务和采用都检查版本，文章恢复不会复活账号偏好。

## 已知实际边界

第二批少量真实运行区分了译文与官方来源，但新题在上限内未完成，不能记为资料充分。第三批ACL初稿与一次编辑在因果措辞、分母及篇幅上部分改善，仍误读原意并保留推断，需人工修订；核查节选未覆盖全文某些操作定义，不等于来源没有这些内容。M1初稿区分了官方原稿与论坛转引，仍有机制和时间外推问题；第二组核查断连，未完成审核和编辑，没有候选稿。

最终公众号提示调整只完成离线回归，未在断连后追加真实生成；旧稿不能证明新提示文风已实测。第四批也未调用付费模型；模拟验证覆盖实际生成链条与功能边界，不保证模型必然准确提炼偏好或改善成稿。累计69/76次请求、未用7次与未知费用原样保留，余量不能自动重用。更多细节见[v1.7.0](RELEASE-1.7.0.md)、[v1.8.0](RELEASE-1.8.0.md)和[v1.9.0](RELEASE-1.9.0.md)。

临时版本评测门槛已按用户要求取消，产品五维审核及人工修订空间未删除。来源错配、错误充分、预算失控及覆盖人工编辑仍须修复；模型误判、外部故障与安全停止如实记录，不把软件发布变成永无终点的语义考试。
